# Simulation and analysis

This directory implements the stochastic and continuum models derived in
[`../manuscript/main.tex`](../manuscript/main.tex). The manuscript is the sole
authority for equations and notation; this document describes execution.

## Implemented descriptions

The `chem_swimmer` package provides:

1. direct simulation of the microscopic position--heading diffusion/jump
   process;
2. a conservative finite-volume density--polarity solver with $Q=0$;
3. the short-time weak-landscape Fourier--Green solution;
4. boundary-layer, nematic, convergence, and inference diagnostics.

Cases 1--9 match the response mechanisms in Table I and Figure 1. Case 0 is
the nutrient-insensitive control. All methods use the sliding/no-flux disk
boundary specified in the manuscript whenever a finite boundary is present.

## Quick start

Python 3.11--3.14 is supported. Local development on the reference workstation
uses the mandatory global Pixi environment named `physics`; its exposed
`python` executable already contains the scientific and CUDA toolchains.

```bash
pixi global list
python --version
PYTHONPATH=src python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

External collaborators who do not share that workstation can use a conventional
virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,figures]"
python -m pytest -q
```

## Reproduce the numerical comparison

```bash
python run.py check --case all
python run.py compare
```

The canonical inputs are in [`config/default.toml`](config/default.toml).
Generated raw data, videos, and diagnostic frames are written below
`results/` but ignored by version control. The comparison pipeline copies the
Case 1 PDF to `../manuscript/figures/figure-3-case-1-validation.pdf` and
copies the Cases 2--9 sheet to
`../manuscript/figures/figure-remaining-cases.pdf` (the supplementary original
stays at `results/figures/supplementary/figure-s01-cases-2-9-summary.pdf`).

Figures 1, 2, 4, 5 and 6 and the supplementary videos are generated by the
scripts in [`scripts/`](scripts/README.md); see the repository README for the
commands.

## Verification and performance

```bash
PYTHONPATH=src python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

FFmpeg is optional and needed only for MP4 rendering and its associated tests.
The production particle solver currently uses Numba on the CPU; CUDA is not a
hidden requirement. On native Linux, an affinity mask can select known core
types. Under WSL it reliably limits guest workers, but the hypervisor may hide
or remap the physical P/E-core placement, so confirm the choice by measurement:

```bash
OMP_NUM_THREADS=8 OMP_PROC_BIND=close OMP_PLACES=cores \
  taskset -c 0-7 python scripts/benchmark_performance.py \
  --threads 8 --batch-size 64 256 1024 --output benchmark.json
```

Thread and batch optima are workload- and machine-dependent. See
[`docs/performance.md`](docs/performance.md) for the measured profile, memory
budget, CUDA assessment, and higher-resolution guidance.

## Code map

- `src/chem_swimmer/simulator.py`: readable microscopic integrator
- `src/chem_swimmer/accelerated.py`: Numba ensemble implementation
- `src/chem_swimmer/moment.py`: finite-volume density--polarity solver
- `src/chem_swimmer/polar_fourier.py`: weak-landscape Fourier solver
- `src/chem_swimmer/kinetics.py`: response laws and macroscopic coefficients
- `src/chem_swimmer/turning.py`: achiral turning kernels
- `src/chem_swimmer/visualization/`: paper and diagnostic plotting
- `tests/test_mathematics.py`: mathematical identities and regressions
- `scripts/`: focused audits and Figure 1 generation
- `docs/repository-audit.md`: evidence-backed engineering audit and roadmap

Generated archives embed their TOML configuration, SHA-256 digest, method,
time grid, sampling settings, and runtime versions. Do not replace a curated
figure without regenerating its supporting metrics from the same archive.
The multi-gigabyte archives under `results/data/` are local caches, not Git
content; publish validated data as a versioned release or archival deposit.
